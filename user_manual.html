1. What is GIS Co-Scientist?

An AI research partner for geographic analysis — from raw question to publishable result.

GIS Co-Scientist (the Autonomous Geographic Modeller, AGM) is a conversational system that lets you carry out geospatial research in plain language. You describe what you want — "download air-quality data for California counties", "test whether obesity rates are spatially clustered", or "write me a paper on PM2.5 and rural classification" — and the system retrieves data, plans the analysis, writes and runs the code, interprets the results, and can even draft a manuscript.

It does this through four working modes that you switch between depending on how much of the pipeline you want the system to run:

Data Retriever

Find and download geospatial datasets from built-in public sources. No analysis.

Spatial Analysis

Run a specific spatial analysis on your data — plan, code, and execute.

Research

The full pipeline: understand the question, plan, analyze, interpret, and write a manuscript.

Chat

Conversational Q&A about GIS concepts, methods, or your data — no workflow is launched.

Who is this for?  Researchers, students, and analysts who want to do spatial analysis without writing all the code themselves. No programming is required, though every piece of generated code is shown to you and can be reviewed, edited, and re-run.

2. Quick Start

Five steps to your first result.

1
Add your GIBD API key. Click Settings (top-right), paste your key (it starts with gibd-) into GIBD API Key, and click Save Key. See Section 3 for how to get one.
2
Pick a mode. In the chat input toolbar, open the mode dropdown (bottom-right of the input box) and choose Data Retriever, Spatial Analysis, Research, or Chat.
3
(Optional) Upload data. Click the ＋ button (or Data layers → Add Data Layer) to load your own shapefile, GeoPackage, GeoJSON, CSV, or raster. If you don't have data, the Data Retriever can fetch it.
4
Type your request in the input box and press Enter (use Shift+Enter for a new line).
5
Review and approve. The system streams its plan, asks for your approval at key checkpoints, then runs. Outputs appear in the Map Viewer and Results & Artifacts panels on the right.
Tip:  Turn on Autonomous mode (in the mode dropdown) if you want the system to auto-approve its own plans and run end-to-end with minimal interruption.

3. GIBD API Key

The key that powers the AI. Required before you can run any mode.

GIS Co-Scientist routes its language-model calls through the GIBD service rather than asking you for an OpenAI key directly. Your personal GIBD key both authenticates you and scopes your private conversation history, so the same key always brings back your chats and uploads.

How to get a key

  1. Go to the GIBD portal at https://www.gibd.online.
  2. Create an account / sign in, and request an API key for the GIS Co-Scientist service.
  3. Copy the key — it will look like gibd-xxxxxxxxxxxxxxxx.

How to enter it

1
Click Settings in the top-right header.
2
Paste the key into the GIBD API Key field. Use the 👁 button to show/hide it.
3
Click Save Key. A status message confirms it was stored. Use Clear Key to remove it.
Where is it stored?  The key is saved locally in your browser only and sent with each request to authenticate. Only keys with the gibd- (or gibd_) prefix are accepted; other keys are rejected and purged automatically.
Keep it private.  Treat your GIBD key like a password. Anyone with it can use your quota and see conversations created under it. Clear it on shared computers.

4. UI Layout Overview

Three resizable regions: a left sidebar, a center chat, and a right panel for the map and results.

Header & top menus

The bar across the top contains:

  • GIBD logo — links to the Penn State GIScience site (giscience.psu.edu).
  • GIS Co-Scientist — the app title.
  • Settings — opens the configuration panel (API keys; see Section 5).
  • Preprint — the academic paper describing the system.
  • User Manual — this document.
  • Video Demo — a YouTube playlist of walkthroughs.

Left sidebar

The collapsible left sidebar (toggle with the ◧ button) has two sections:

  • Data layers — every dataset you've uploaded or that the system has retrieved. The folder ＋ button adds a new layer. Each layer has its own drop-down menu (see Section 6).
  • Conversation History — your saved chats, newest first. New chat starts a fresh conversation (see Section 7).

Center — chat area

The middle column is the conversation itself: the assistant's messages and a multi-line input box at the bottom. Below the input box is a toolbar:

  • ＋ Add data — upload a dataset (same as the sidebar button).
  • Auto Data — toggles automatic data downloading on/off (see Section 9).
  • Mode selector — choose the working mode and the Autonomous toggle.
  • Model selector — choose the language model and its Reasoning Effort.
  • EDA — optional exploratory data analysis before planning (when enabled).
  • Send ➤ — submit your request (also doubles as a Stop button while running).

Right — map & results

The right region is split top/bottom and can be collapsed with the ◨ button:

  • Map Viewer (top) — an interactive map that renders your data layers and analysis outputs.
  • Results & Artifacts (bottom) — generated code, tables, figures, statistics, and report downloads. Clear it with the × button.
Resizing:  Drag the dividers between panels to resize them, and use the collapse arrows (◧ / ◨) to hide a panel entirely and give the chat more room.

5. Settings

Opened from the Settings button. Two things live here.

GIBD API Key

Enter, show/hide, save, or clear your GIBD key — covered in Section 3.

Data Source Keys

Some data sources (e.g. the U.S. Census, EPA AQS) require their own free API keys. This section lets you store those keys once so you're not asked again:

  • When a download needs a key you don't have, the system prompts you inline in the chat. Whatever you enter is saved here automatically.
  • You can also add keys ahead of time: type the key name (e.g. US_Census_demography_key) and its value, then click Add.
  • Saved keys are listed and can be removed individually.

See Section 9 for exactly which sources need a key and where to get one.

7. Conversation History & Sharing

Your work is saved automatically and scoped to your GIBD key.

History

  • New chat starts a fresh conversation with its own data layers and workspace.
  • Conversations are listed in the left sidebar and saved against your GIBD key — sign in with the same key on any machine to get them back.
  • You can rename or delete a conversation you own. (Deletion is owner-only.)
  • Uploaded files and generated artifacts are stored with the conversation, so reopening it restores its state.

Sharing a conversation

Every conversation has a shareable URL — the browser address updates to include ?conversation=<id> as soon as the chat is created. To share, simply copy that link and send it.

What happens when someone opens your link

SituationBehavior
You (the owner) open itFull edit access, as normal.
Another user opens it (with their own key) They join as a collaborator. A banner notes it's a shared conversation; both of you see updates in the same workspace and artifacts.
A collaborator wants a private copy Fork-on-write: their first change can create an independent copy they own, leaving your original untouched. (Forking is blocked while a run is still in progress.)
Note:  Only the owner can rename or delete the original. Collaborators see and contribute to the live conversation but cannot remove it.

8. Modes, Models & Autonomous

Three small controls in the input toolbar shape how every request is handled.

Choosing a mode

Open the mode dropdown (bottom-right of the input box, labeled with the current mode) and pick one:

ModeUse it to…Section
Data RetrieverDownload data only — no analysis.§9
Spatial AnalysisRun a direct spatial analysis on your data.§10
ResearchRun the full workflow and draft a manuscript.§11
ChatAsk conversational questions, no workflow.§12

Autonomous mode

Inside the mode dropdown is an Autonomous toggle. When on, the system auto-approves its own plans and proceeds through checkpoints without pausing for your confirmation — useful for hands-off, end-to-end runs. When off (the default), it stops at each major checkpoint so you can review, revise, or approve.

When to use it:  Turn Autonomous on once you trust the request and want a complete result in one go; keep it off when you want to steer the analysis step by step.

Model & reasoning effort

The model dropdown selects the language model (e.g. GPT-5.2 / 5.3 / 5.4 and the GPT-4.1 / GPT-4o families). Newer models expose a Reasoning Effort sub-menu — typically none, low, medium, high, and xhigh. Higher effort means deeper reasoning (slower, more thorough); lower effort is faster. Medium is a good default.

Tip:  Use higher reasoning effort and a top-tier model for complex Research-mode work; a lighter model is fine for quick data pulls or Chat.

9. Data Retriever Mode

Data Retriever Find and download geospatial datasets from built-in public sources — without running any analysis.

How to use it

1
Switch the mode to Data Retriever.
2
Describe what you need in natural language, including variable, place, and time. For example:
"Download 2019 county-level PM2.5 from EPA AQS for California."
"Get census-tract median household income for Pennsylvania."
"Fetch a 30 m DEM for the area around State College, PA."
3
The system identifies the best matching data source, fetches the data, and adds it as a new data layer you can map and download.

The "Auto Data" toggle

The Auto Data button in the input toolbar controls whether data needed for a request is downloaded automatically. With it on, the system pulls required datasets without asking each time; with it off, it pauses for your confirmation before downloading. This toggle is also respected by Spatial Analysis and Research modes when they need extra data.

Enter these once under Settings → Data Source Keys (or when prompted), and they're reused thereafter.

Downloading multiple datasets

You can ask for several datasets in one request (e.g. "download 2019 county boundaries and county-level obesity rates for California"). The system retrieves each one and adds them as separate data layers. Each is independently mappable and downloadable, and ready to be merged later in Spatial Analysis or Research mode.

Feedback & approval prompts

Data retrieval is interactive. You may be asked to respond at two points:

  • Source confirmation — if the system isn't fully sure which source to use, it asks you to use the proposed source, retry with a different one, or abort.
  • Download fallback — if a download fails or a needed file is missing, you can choose to proceed with available data, upload the missing file yourself, or abort the workflow. Uploaded files are audited automatically and folded into the run.
Best practice:  Be specific about year, geography level (county vs. tract), and variable name. Vague requests lead to more clarification prompts.

10. Spatial Analysis Mode

Spatial Analysis Run a specific spatial analysis on your data — the system plans the geoprocessing workflow, writes the code, and executes it.

How to use it

1
Upload (or retrieve) the dataset(s) you want to analyze.
2
Switch the mode to Spatial Analysis.
3
State the analysis you want — for example:
"Test whether county obesity rates in California are spatially clustered."
"Run a GWR of PM2.5 on income and rural classification."
4
Review the proposed geoprocessing workflow. You can approve it, or send feedback to revise it before anything runs.
5
The system generates the code, executes it, and returns maps, tables, statistics, and figures in the Results panel.

What it can do

The system draws on a curated knowledge base of spatial-analysis methods, including:

CategoryMethods
Data preparationDataset merging / joins, spatial-weights construction.
Spatial autocorrelationGlobal Moran's I, Local Moran's I (LISA cluster maps).
CorrelationBivariate correlation, correlation matrices.
RegressionOLS regression, spatial regression (lag / error), GWR (geographically weighted regression).

Reviewing & re-running

  • Code review — generated Python is shown with syntax highlighting; you can read it before it runs.
  • Revise — give feedback in plain language and the workflow or code is regenerated.
  • Re-run steps — individual steps can be re-executed without restarting the whole analysis.
  • EDA toggle — optionally run exploratory data analysis first to understand your data before planning.
Autonomous + Spatial Analysis:  With Autonomous on, the workflow and code are auto-approved and the analysis runs straight through.

11. Research Mode

Research The complete pipeline — from research question to a drafted manuscript, including interpretation of results.

Research mode is the most comprehensive mode. Give it a research question and (optionally) data, and it works through the entire scientific process, pausing for your approval at each major checkpoint (unless Autonomous is on).

The workflow stages

1
Question understanding & breakdown — the system interprets your research question and breaks it into concrete analytical tasks. You review the breakdown and can ask it to revise or proceed.
2
Research plan — a step-by-step plan (data, methods, analyses) is drafted and shown as a flowchart / geoprocessing workflow. Approve or revise it.
3
Data acquisition — required datasets are retrieved (subject to the Auto Data setting) or taken from your uploads.
4
Code generation & execution — each analysis step is implemented in code and run; intermediate outputs accumulate in the Results panel.
5
Result analysis — outputs are interpreted: a presentation of findings, a discussion, rendered figures, and equations.
6
Manuscript drafting — a full paper is written section by section.

The manuscript deliverable

The reporting pipeline produces a structured research paper with standard academic sections:

  • Title & Abstract — including structured Background / Methods / Results / Conclusions and keywords.
  • Introduction — framed with literature and study objectives.
  • Methods — data sources, study area, and analytical methods.
  • Results — quantitative findings with figures and tables.
  • Discussion & Conclusion — interpretation, significance, and implications.

Figures generated during analysis can be promoted into the manuscript (or demoted), and the finished report can be downloaded. Individual stages — analysis, manuscript, specific steps — can be re-run or refined without starting over.

Get the most out of Research mode:  State a clear research question with a study area and variables (e.g. "How is PM2.5 associated with rural classification across California counties in 2019?"), use a capable model with higher reasoning effort, and review each checkpoint rather than running fully autonomous on the first try.

12. Chat Mode

Chat Plain conversational Q&A — no workflow is launched.

Use Chat mode to ask questions, clarify concepts, or plan your approach before committing to an analysis. For example:

  • "What's the difference between Global and Local Moran's I?"
  • "Which data source should I use for county-level income?"
  • "How should I frame a study of air quality and rurality?"

Chat mode answers directly without generating or running code, making it the fastest way to think through your project. When you're ready to act, switch to Data Retriever, Spatial Analysis, or Research mode.

13. Results, Map & Artifacts

Where outputs land and how to work with them.

Map Viewer

  • Renders your uploaded layers and analysis outputs on an interactive map.
  • Use a layer's Load on Map Viewer menu action (or its visibility checkbox) to control what's shown.
  • Result layers produced by an analysis can be added back to the map and downloaded like any other layer.

Results & Artifacts

  • Generated code — shown with syntax highlighting and a copy button.
  • Tables & statistics — model summaries, attribute previews, and numeric results.
  • Figures — charts and maps; promote the best ones into a manuscript.
  • Reports — drafted result presentations, discussions, and manuscripts, downloadable in document formats.
  • Clear the panel anytime with the × button; artifacts remain saved with the conversation.

14. Tips & Troubleshooting

SymptomWhat to check
Nothing runs / "API key required"Add a valid GIBD key (starts with gibd-) in Settings and click Save Key.
A data download is rejected for "missing key"The source needs a free API key — add it under Settings → Data Source Keys, or enter it when prompted. See §9.
Wrong dataset retrievedBe explicit about year, geography level, and variable; or name the source directly. Use the source-confirmation prompt to retry.
Shapefile won't loadInclude all components (.shp .shx .dbf .prj) or upload them as a single .zip.
My conversations disappearedThey're tied to your GIBD key — make sure the same key is entered.
Can't delete a shared conversationOnly the owner can delete/rename; collaborators have shared access only.
Run feels slowLower the Reasoning Effort or choose a lighter model for simple tasks.
Too many approval promptsTurn on Autonomous mode to auto-approve plans.

General best practices

  • Start in Chat to scope the problem, then move to an action mode.
  • Keep requests specific: variable + place + time.
  • Review the plan/code at checkpoints before approving — especially on the first run of a new analysis.
  • Use higher-tier models and reasoning effort for Research mode; lighter ones for quick data pulls.
  • Save reusable data-source keys once in Settings to avoid repeat prompts.
